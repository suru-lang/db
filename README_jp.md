# 蔵(する のデータベースの層)

日本語のプログラミング言語「[する](https://github.com/suru-lang/suru)」の、データベースの薄い層です。決めるのは つなぐ・実行する・行を取り出す・トランザクション だけなので、駆動の名前を1つ替えるだけで、同じプログラムが SQLite・PostgreSQL・MySQL を使えます。する だけで書いてあり、C のライブラリは要りません。駆動はそれぞれのリポジトリにあります。この上に [suru-lang/orm](https://github.com/suru-lang/orm) の O/R マッパーを作る予定です(計画: suru-lang/suru#164)。

## 入れ方

[kumu](https://github.com/suru-lang/suru/blob/main/README_jp.md#プロジェクトを組むkumu) のプロジェクトで、この層と、使うデータベースの駆動を足します:

```sh
kumu 追加 github.com/suru-lang/db
kumu 追加 github.com/suru-lang/sqlite
```

| データベース | 駆動 | リポジトリ |
|---|---|---|
| SQLite | `SQLite駆動` | [suru-lang/sqlite](https://github.com/suru-lang/sqlite)(v0.2.0 で入る予定) |
| PostgreSQL | `PostgreSQL駆動` | [suru-lang/postgresql](https://github.com/suru-lang/postgresql)(予定) |
| MySQL | `MySQL駆動` | [suru-lang/mysql](https://github.com/suru-lang/mysql)(予定) |

## 使い方

```
「蔵」 を 読み込んで 使う
「SQLite」 を 読み込んで 使う

DB行 を 名前取得する は 文字列
行 を 名前取得する とは 行 から 「名前」 を DB列取得して DB文字列取出する

主処理する とは 入出力手順
  db とは 「店.db」 を SQLite駆動 で DB開封した 結果
  db に 「CREATE TABLE IF NOT EXISTS 品 (名前 TEXT, 値段 REAL)」 を DB実行する
  db に 「INSERT INTO 品 VALUES (?, ?)」 を （（「りんご」 の DB文字列） と （120 の DB数）） で DB差込実行する
  行群 とは db に 「SELECT 名前, 値段 FROM 品 WHERE 値段 < ?」 を （（200 の DB数） を 空 に 挿入する） で DB行問合した 結果
  （行群 の それぞれ を 名前取得して 改行 で 結合する） を 表示する
  db を DB閉鎖する
  「以上です」 を 表示する

主処理する
```

PostgreSQL にするなら、`「PostgreSQL」 を 読み込んで 使う` と `… を PostgreSQL駆動 で DB開封した 結果` に替えます。ほかはそのままです。名前はどれも `DB` で始まります。`「蔵」 を 読み込む` なら `蔵内のDB開封する` のように「蔵内の」を付けます。

## 決めたこと

1. **駆動でつなぐ。** `先 を 駆動 で DB開封する` でつなぎ、接続(`DB接続`)を受け取ります。`先` の意味は駆動ごとです(SQLite ならファイルの道)。`db を DB閉鎖する` で閉じます。データベースを触る関数はどれも動作です。
2. **値は選択肢のある型 `DB値`。** `DB無`(NULL)、`42 の DB数`(整数も小数も)、`「a」 の DB文字列`、`b の DBバイト列`、`真 の DB真偽` です。読んだ値もこの型です。`v を DB数取出する`(ほかに `DB文字列取出する`・`DBバイト列取出する`・`DB真偽取出する`)で中の値を取り出し、違う形なら実行時エラーです。SQLite と MySQL は真偽を数で持つので、`DB真偽取出する` は数の 1 と 0 も受け付けます。`v を DB値文字列にする` は表示のための文字列です(`DB無` は「NULL」)。
3. **実行と問い合わせ。** `db に 文 を DB実行する` は結果の行のない SQL を実行して、変わった行の数を返します。`db に 文 を DB問合する` は結果の行(1行は列の順の `DB値` のリスト)のリストです。`db を DB最終番号取得する` は最後の INSERT で自動採番された番号です。
4. **値は「?」に入れる。** `DB差込実行する` と `DB差込問合する` は「で」に `DB値` のリストを受け取り、文の「?」に前から順に入れます。プレースホルダは、どのデータベースでもいつも「?」と書きます。PostgreSQL の駆動は `文 を DB番号差込変換する` で `$1, $2, …` に書き換えます(文字列と囲んだ名前の中の「?」はそのまま)。
5. **列の名前で引く行。** `db に 文 を 値群 で DB行問合する` は `DB行` の行を返し、`行 から 「名前」 を DB列取得する` でその列の値を取り出します(ない列なら実行時エラー)。
6. **トランザクション。** `db で 処理 を DB取引する` は、動作 `処理` を BEGIN と COMMIT の間で行い、その結果を返します。`処理` が実行時エラーになったら ROLLBACK して、同じ文で失敗します(`試行する` で受け止められます)。
7. **方言。** 接続はデータベースの違いをまとめた `DB方言`(`db の DB方言値`)を持ちます。名前を囲む字、整数・小数・文字列・バイト列・真偽・自動採番の主鍵の列の型、`INSERT … RETURNING` を使えるかです。`DBSQLite方言`・`DBPostgreSQL方言`・`DBMySQL方言` があります。`名前 を 方言 で DB名囲みする` は表や列の名前を囲みます(`"名前"`、MySQL は `` `名前` ``)。O/R マッパーはこれを見て SQL を組み立てます。
8. **失敗は実行時エラー。** 駆動はデータベースの理由つきで失敗し、`試行する` で受け止められます。

## 駆動を作る

駆動は `名前 と 開く関数 の DB駆動` です。開く関数は `先` を受け取って `DB接続` を返す動作です。`DB接続` は、次の5つの項目をこの順に持つ組です:

1. `DB実行口`: 変わった行の数を返す `文 を 値群 で …` の関数(動作)。
2. `DB問合口`: 列の名前と行 `列名群 と 行群 の DB問合結果` を返す `文 を 値群 で …` の関数(動作)。
3. `DB最終番号口`: 最後に自動採番された番号を返す動作。
4. `DB閉鎖口`: 接続を閉じる動作。
5. `DB方言値`: `DB方言`。

関数は、駆動の関数をつないだ相手に部分適用して作ります(`（h に 低実行すること）` のように)。[試験/層.suru](試験/層.suru) に、この形で書いた偽の駆動があります。

## 試験

```sh
kumu 試験
kumu 点検
```

試験は、受け取った SQL をファイルに書く偽の駆動を使うので、データベースは要りません。駆動はそれぞれ、本物のデータベースで試験します。
